# Applicable legal sources — `HvA_full_dmn_export.dmn`

Generated by [`extract-legal-sources.py`](extract-legal-sources.py) from the **original** `HvA_full_dmn_export.dmn` and `HvA_annotaties.xml` — read-only, regenerate any time either file is re-exported:

```bash
cd examples/organizations/amsterdam/testCases
python extract-legal-sources.py
```

Walks every decision's `<dmn:authorityRequirement>` → `<dmn:knowledgeSource>` link, resolves the CPT (concept) or APT (text annotation) id it points at against `HvA_annotaties.xml`'s own registries, and reports the named source document (with its BWB number where the document _is_ a national law), the JuriConnect (JCI) article-level citation where the underlying annotation carries one, and the grounding quote itself. Also emits [`legal-sources-hva.json`](legal-sources-hva.json) with the full, unabridged data (untrimmed quotes, every matched document/citation) for anything that wants to consume this programmatically.

## Known data-quality caveats

- **`HvA_annotaties.xml` is not well-formed XML** — a handful of `<property>` attribute values contain unescaped nested double quotes. Parsed with lxml's recovering parser, which drops only the malformed fragment, not the surrounding document; one `<textannotation>` out of the file's 359 was lost this way (358 recovered here). Not something this script can fix — it's a defect in the source export, independent of the FEEL-evaluation fix in `HvA_full_dmn_export-patched.dmn`.
- **2 documents' `name` is just their raw BWB number** (`BWBR0005416`, `BWBR0035362`) with no human-readable title filled in on the source side — shown as-is above.
- **2 `authorityRequirement` link(s)** (across 2 decision(s), 1 distinct dangling `knowledgeSource`) point at a CPT/APT id that isn't in the annotation export at all — see "Unresolved links" above.
- Only **72 of 358** text annotations carry an article-level JuriConnect citation at all (~20%), and those 72 share only **23 distinct citation values** between them (the same article commonly grounds several separately-quoted concepts). The rest ground to a named document and a quote, but not a specific article — that's a real gap in what iKnow's export captured, not something this script can infer.
